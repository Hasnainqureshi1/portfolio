# Search growth opportunities and content briefs

Research date: 27 October 2026. Purpose: determine what to add to existing pages, which new pages merit work, and whether more tools will help attract UK/US prospective clients. This extends the same-day technical audit; it does not replace it. The visual theme and production pages were not changed.

## Recommendation

Improve the existing Next.js/headless WordPress service and its project evidence first. Build one substantial migration-planning guide and improve the relevant existing tools around that workflow. Support the commercial-property service with stronger project implementation evidence and its existing checklist. Expand SaaS content after those commercial paths are measurable.

A dedicated agency-support service is a useful second-stage option if the owner confirms the working arrangement and availability. A redirect-map checker is a conditional experiment, not the first investment: several tools already offer the basic CSV chains/loops/duplicate checks. The proposed website would need a useful distinction and a route to actual implementation enquiries.

## What “10x” means

The supplied baseline is 11 Google clicks and 16 GA4 organic sessions in the selected 28-day periods. A tenfold target would be 110 Google clicks or 160 organic sessions, respectively. These are different measurements. Neither number means 50 qualified prospects or 50 enquiries.

At the screenshot's rounded 3.6% CTR, 110 clicks would require roughly 3,056 impressions if CTR stayed constant. This is arithmetic, not a forecast: query mix, country, position and buyer fit are unknown. Track relevant service/case-study visits from the UK/US separately, and classify actual enquiries by project fit.

The planning goal is more buyer-relevant exposure with measurable paths to enquiry. No public search result, schema change, publishing quota or tool guarantees 10x growth. Use a 90-day experiment with intermediate reviews, not a promised ranking deadline.

## Research method and limits

- Reviewed the current heading structure of all 30 sitemap pages and inspected the Next.js, property, SaaS, calculator, brief builder, feedback and health-check implementations.
- Reused the same-day live audit: 30 canonical pages and 67 other linked resources were accessible. Browser checks and the measurement defects are documented separately.
- Searched public results for freelance/agency Next.js work, headless WordPress cost/comparisons/migrations, property briefing, SaaS scope templates and redirect-map tools. Opened representative first-party competitor pages and official Google/Next.js documentation.
- This is public web-search and competitor research, not an authenticated Google Keyword Planner export, London-simulated Google ranking report, backlink-index export or traffic estimate. Competition examples establish existing supply and possible intent; they do not measure demand or difficulty.
- Keyword volumes, organic difficulty, current UK/US non-brand rankings and page-level enquiry conversion are unverified. No invented values are used below.

## New-page backlog in publication order

### 1. WordPress-to-Next.js migration planning guide

Proposed URL: `/insights/wordpress-to-nextjs-migration-checklist/`

Candidate title: **WordPress to Next.js Migration Checklist: Content, URLs and Editors**

Audience: a business/agency evaluating implementation; developers doing the work are a secondary audience. Search families: WordPress to Next.js migration checklist, WordPress Next.js migration SEO, headless WordPress migration.

Required outline:

1. Decide whether a separate frontend solves a real need.
2. Inventory page types, fields, media, menus, integrations and existing public URLs.
3. Map content to components with an original synthetic ACF-style example.
4. Agree preview/publishing ownership and protected draft access.
5. Preserve URL intent and plan mappings when addresses change.
6. Check canonicals, metadata, sitemap, internal links and forms.
7. Define staging review, release checks and rollback responsibility.
8. Download an original inventory/checklist and discuss implementation scope.

Differentiation: a worked content/URL inventory plus a field-to-page example, not another generic checklist. The portfolio demonstrates headless implementation; it does not establish that either featured project was a migration. Keep that distinction explicit.

Link from Next.js service → guide → relevant case study → project enquiry. Google's migration guidance and current Next.js preview docs provide references for technical claims. Do not promise “no traffic loss.”

## Conditional new tool: migration redirect-map checker

Proposed URL if evidence supports it: `/tools/redirect-map-checker/`

Public results already include Redirections, Sitechecker, QCK and multiple browser CSV checkers. Basic chain/loop/duplicate detection is not a distinctive gap. The tool is a later experiment after relevant demand, guide engagement or agency feedback appears.

Potential distinctive scope: accept an old-URL inventory plus a proposed map; identify old URLs without a decision, competing sources, loops, chains and unsupported rules; let the user mark keep/redirect/remove for review; export a decision/QA report. Provide original failing/reviewed examples. Keep structural local checks separate from live status checks. Regex/server behavior, page relevance, destination availability and deployed responses require additional validation; do not present a clean spreadsheet as a guaranteed successful migration.

This could reuse CSV parsing knowledge, but remains a separate implementation with meaningful edge-case tests. A live crawler would add network, scope and operating requirements. Link the result to the migration guide and implementation offer. Acceptance in a directory or rankings cannot be assumed.

## Publication and distribution plan

**Days 1–14:** Fix the confirmed measurement/host issues from the technical audit, validate two priority query groups, improve the Next.js offer and project evidence. Keep URL and theme stability. Establish the same reporting window and event definitions.

**Days 15–30:** Publish the original migration guide and its downloadable example; add contextual internal links. Improve the property implementation example and distribute the existing checklist to a relevant audience through an approved action.

**Days 31–60:** Publish one decision-stage guide or agency service only after owner/demand validation. Improve cost/brief planning where visitors' tasks justify it. Seek accurate project credits and relevant references. Record actual linking pages and referrals.

**Days 61–90:** Review non-brand queries/countries and which pages bring service interest. Extend the successful cluster. Consider the redirect-map tool only if its need is established. A review checkpoint is not a guaranteed growth deadline.

For each original article, prepare a useful standalone excerpt for an owned professional profile, a relevant repository reference where appropriate, and a small number of editorial/resource opportunities. Existing collaborators can review attribution and decide whether to credit the work. Developer publications may yield peer traffic; assess whether it reaches agencies or relevant services. No unsolicited messages or external posts were sent in this research.

## Validation before committing the backlog

Use the companion `growth-keyword-validation-2026-10-27.csv` as seeds. Run Keyword Planner separately for London, UK and US, with consistent network/language/date settings. Also test location-unmodified terms using location filters. London is part of the UK; do not add overlapping location totals. Advertiser competition is not organic difficulty, and ad forecasts are not organic predictions.

From Search Console, review Queries, Pages and Countries for the same three-month period and a comparable 28-day comparison. Separate name/domain searches from service queries. For GA4, compare organic landing pages/countries and task-to-service/enquiry events. The screenshot's country card set to Yesterday is not a monthly audience report.

Track: non-brand Google impressions/clicks; UK/US organic service/case-study sessions; useful tool completions; service transitions; actual enquiries; manually qualified enquiries. Country and landing page are a proxy, not proof of a buyer. Use real project budget, availability and working hours to qualify demand.
